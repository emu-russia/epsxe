Overview

GTE не имеет отображения на шину памяти CPU — доступ осуществляется исключительно через сопроцессорные коды:

mov  cop0r12,rt          ;- enable/disable COP2 (GTE) via COP0 status register
mov  cop2r0-63,rt        ;- write parameters to GTE registers
mov  cop2r0-31,[rs+imm]  ;/
mov  cop2cmd,imm25       ;- issue GTE command
mov  rt,cop2r0-63        ;- read results from GTE registers
mov  [rs+imm],cop2r0-31  ;/
jt   cop2flg,dest        ;- jump never  ; implemented, but flag always false
jf   cop2flg,dest        ;- jump always ;/

Задержки: команды загрузки/сохранения имеют задержку в 2 инструкции. Команды GTE не должны использоваться в слотах задержки переходов или в обработчиках прерываний.

Если чтение регистра или команда GTE выполняются до завершения текущей, CPU приостанавливается до окончания. Такты каждой команды указаны в списке.

Формат команды GTE (COP2 imm25)

  31-25  Must be 0100101b for "COP2 imm25" instructions
  20-24  Fake GTE Command Number (00h..1Fh) (ignored by hardware)
  19     sf - Shift Fraction in IR registers (0=No fraction, 1=12bit fraction)
  17-18  MVMVA Multiply Matrix    (0=Rotation. 1=Light, 2=Color, 3=Reserved)
  15-16  MVMVA Multiply Vector    (0=V0, 1=V1, 2=V2, 3=IR/long)
  13-14  MVMVA Translation Vector (0=TR, 1=BK, 2=FC/Bugged, 3=None)
  11-12  Always zero
  10     lm - Saturate IR1,IR2,IR3 result (0=To -8000h..+7FFFh, 1=To 0..+7FFFh)
  6-9    Always zero
  0-5    Real GTE Command Number (00h..3Fh) (used by hardware)

Биты MVMVA используются только командой MVMVA. Биты sf и lm обычно фиксированы (кроме MVMVA и некоторых команд).

Saturation & FLAG

Переполнения фиксируются в регистре FLAG (cop2r63). В большинстве случаев результат насыщается до MIN/MAX (кроме MAC0–MAC3). Для IR1–IR3 бит lm выбирает минимальное значение.

БитОписание
31Error Flag (OR битов 30..23 и 18..13)
30–28MAC1–MAC3 положительное переполнение (44-bit)
27–25MAC1–MAC3 отрицательное переполнение
24–22IR1–IR3 насыщение (зависит от lm)
21–19Color-FIFO R/G/B насыщение до 00..FF
18SZ3 или OTZ насыщение до 0000..FFFF
17Divide overflow (RTPS/RTPT)
16–15MAC0 переполнение (32-bit)
14–13SX2/SY2 насыщение до -0400..03FF
12IR0 насыщение до 0000..1000

Биты 30–12 доступны для чтения/записи, но автоматически сбрасываются в начале новой команды GTE.

Важно: запись 32-битных значений в 16-битные регистры не вызывает насыщения и не устанавливает флагов.

Команды координатных вычислений

RTPS / RTPT

RTPS (15 тактов) — перспективное преобразование одной вершины (V0). RTPT (23 такта) — повтор для V1 и V2.

IR1 = MAC1 = (TRX*1000h + RT11*VX0 + RT12*VY0 + RT13*VZ0) SAR (sf*12)
IR2 = MAC2 = (TRY*1000h + RT21*VX0 + RT22*VY0 + RT23*VZ0) SAR (sf*12)
IR3 = MAC3 = (TRZ*1000h + RT31*VX0 + RT32*VY0 + RT33*VZ0) SAR (sf*12)
SZ3 = MAC3 SAR ((1-sf)*12)                           ; ScreenZ FIFO
MAC0 = (((H*20000h/SZ3)+1)/2)*IR1 + OFX, SX2 = MAC0/10000h
MAC0 = (((H*20000h/SZ3)+1)/2)*IR2 + OFY, SY2 = MAC0/10000h
MAC0 = (((H*20000h/SZ3)+1)/2)*DQA + DQB, IR0 = MAC0/1000h

Если результат деления > 1FFFFh — насыщение и флаг Divide Overflow. Для RTPT вычисление DQA/DQB/IR0 выполняется только для третьей вершины (V2).

NCLIP

NCLIP (8 тактов) — вычисление знака площади треугольника по координатам SXY0–SXY2:

MAC0 = SX0*SY1 + SX1*SY2 + SX2*SY0 - SX0*SY2 - SX1*SY0 - SX2*SY1

Знак определяет ориентацию (по часовой/против). Нуль — вырожденный треугольник.

AVSZ3 / AVSZ4

Усреднение Z-значений для Ordering Table:

MAC0 = ZSF3*(SZ1+SZ2+SZ3)   ; AVSZ3
MAC0 = ZSF4*(SZ0+SZ1+SZ2+SZ3) ; AVSZ4
OTZ  = MAC0/1000h (saturated to 0..FFFFh)

Обычно ZSF3 = N/30h, ZSF4 = N/40h, где N — размер таблицы.

Общие вычисления

MVMVA

Умножение вектора на матрицу и сложение с вектором переноса.

MAC1 = (Tx1*1000h + Mx11*Vx1 + Mx12*Vx2 + Mx13*Vx3) SAR (sf*12)
MAC2 = (Tx2*1000h + Mx21*Vx1 + Mx22*Vx2 + Mx23*Vx3) SAR (sf*12)
MAC3 = (Tx3*1000h + Mx31*Vx1 + Mx32*Vx2 + Mx33*Vx3) SAR (sf*12)
[IR1,IR2,IR3] = [MAC1,MAC2,MAC3]

Параметры mx, v, cv выбирают матрицу, вектор и перенос. При v=2 (FC) вектор добавляется некорректно (баг).

SQR

Квадрат вектора IR:

[MAC1,MAC2,MAC3] = [IR1², IR2², IR3²] SHR (sf*12)
[IR1,IR2,IR3] = [MAC1,MAC2,MAC3] (saturated to max 7FFFh)

OP

Внешнее произведение двух векторов (IR и D, где D — элементы RT-матрицы):

[MAC1,MAC2,MAC3] = [IR3*D2 - IR2*D3, IR1*D3 - IR3*D1, IR2*D1 - IR1*D2] SAR (sf*12)

LZCS / LZCR

Подсчёт ведущих нулей/единиц. Запись в LZCS, чтение из LZCR — результат от 1 до 32.

Цветовые команды

Группа команд NCS, NCT, NCCS, NCCT, NCDS, NCDT, CC, CDP, DCPL, DPCS, DPCT, INTPL, GPF, GPL — работают с цветовыми FIFO, матрицами освещения и цветовыми преобразованиями.

Общая схема (для NCDx / NCCx)

[IR1,IR2,IR3] = (LLM * V0) SAR (sf*12)
[IR1,IR2,IR3] = (BK*1000h + LCM * IR) SAR (sf*12)
[MAC1,MAC2,MAC3] = [R*IR1, G*IR2, B*IR3] SHL 4
[MAC1,MAC2,MAC3] = MAC + (FC - MAC)*IR0   ; только для NCDx
[MAC1,MAC2,MAC3] = [MAC1,MAC2,MAC3] SAR (sf*12)
Color FIFO = [MAC1/16, MAC2/16, MAC3/16, CODE]
[IR1,IR2,IR3] = [MAC1,MAC2,MAC3]

DPCS / DPCT / DCPL / INTPL

Выполняют интерполяцию с учётом глубины или смешивание с дальним цветом. Например, для DPCS:

[MAC1,MAC2,MAC3] = [R,G,B] SHL 16
[MAC1,MAC2,MAC3] = MAC + (FC - MAC)*IR0
[MAC1,MAC2,MAC3] = [MAC1,MAC2,MAC3] SAR (sf*12)
Color FIFO = [MAC1/16, MAC2/16, MAC3/16, CODE]

GPF / GPL

Общая интерполяция:

[MAC1,MAC2,MAC3] = 0   ; для GPF
[MAC1,MAC2,MAC3] = [MAC1,MAC2,MAC3] SHL (sf*12)   ; для GPL
[MAC1,MAC2,MAC3] = ([IR1,IR2,IR3] * IR0 + [MAC1,MAC2,MAC3]) SAR (sf*12)
Color FIFO = [MAC1/16, MAC2/16, MAC3/16, CODE]

IRGB/ORGB — преобразование 5:5:5 ↔ 16:16:16.

Неточность деления GTE

Для RTPS/RTPT используется быстрый алгоритм, основанный на Unsigned Newton-Raphson (UNR). Аппаратно:

if (H < SZ3*2) then
    z = count_leading_zeroes(SZ3)
    n = (H SHL z)
    d = (SZ3 SHL z)               ; d в диапазоне 8000h..FFFFh
    u = unr_table[(d-7FC0h) SHR 7] + 101h
    d = ((2000080h - (d * u)) SHR 8)
    d = ((0000080h + (d * u)) SHR 8)
    n = min(1FFFFh, (((n*d) + 8000h) SHR 16))
else n = 1FFFFh, FLAG.Bit17=1, FLAG.Bit31=1

Таблица unr_table (257 записей) приведена в документе. Результат насыщается до 1FFFFh при переполнении, но без установки флага переполнения, если это вызвано особенностями UNR.

Особенности: деление на 0000h или очень маленькие значения приводит к насыщению и установке флагов. Для точных вычислений рекомендуется программная проверка.
